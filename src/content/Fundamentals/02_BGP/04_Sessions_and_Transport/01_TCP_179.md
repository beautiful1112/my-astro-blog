# BGP transport over TCP 179

BGP uses **TCP port 179** (RFC 4271). TCP provides reliable, ordered byte delivery, retransmission, and handling of segmentation—so BGP can focus on routing state rather than inventing its own reliability layer. The initiating side typically uses an ephemeral source port toward destination 179; **either peer may initiate** unless configured passive.

## What TCP gives BGP—and what it does not

| TCP provides | TCP does not provide |
|---|---|
| Reliable ordered byte stream | Correct routing policy |
| Retransmission of lost segments | Detection of pure forwarding failures on alternate paths |
| Connection liveness (to a point) | Guarantee that OPEN/capabilities will succeed |
| Single session abstraction | Per-AFI/SAFI usefulness |

A three-way handshake can complete while OPEN negotiation fails. An Established BGP session can exchange **zero** accepted routes. Network policy must permit initiation behavior and return traffic in both directions.

Related: [FSM](../05_FSM_and_Timers/01_Finite_State_Machine.md), [Session protection](05_Session_Authentication_and_GTSM.md).

## Path and middlebox hazards

- Stateful firewalls and NAT breaking asymmetric or long-lived sessions;
- MSS/MTU black holes (PMTUD issues) causing stuck opens or stalled UPDATEs;
- Control-plane policing dropping TCP 179 bursts during convergence;
- ACLs allowing only one initiation direction while both sides are active;
- AnyCast or ECMP changing mid-session paths without fate-sharing.

## Configuration patterns

### Cisco IOS / IOS XE

```text
router bgp 65000
 neighbor 198.51.100.1 remote-as 64496
 ! optional: neighbor 198.51.100.1 transport connection-mode passive
```

### Junos

```text
set protocols bgp group EXT peer-as 64496
set protocols bgp group EXT neighbor 198.51.100.1
set protocols bgp group EXT neighbor 198.51.100.1 passive
```

### FRRouting

```text
router bgp 65000
 neighbor 198.51.100.1 remote-as 64496
 neighbor 198.51.100.1 passive
```

Infrastructure ACL sketch (conceptual): permit tcp to/from peer with dport or sport 179 as required by initiation design.

## Interactions

| Mechanism | Interaction |
|---|---|
| MD5 / TCP-AO | Authenticates TCP segments; mis-match → TCP never stably establishes |
| GTSM | TTL check on IP header before BGP trusts the peer |
| BFD | Parallel liveness; can tear BGP faster than Hold Timer |
| Multihop | TCP may succeed across many hops while forwarding path for NLRI next hops differs |

## Verification

```text
show tcp brief | include 179
show bgp neighbors 198.51.100.1
show ip bgp summary
# capture: tcp port 179
```

Lab checks:

1. Block port 179 one way; observe Idle/Active vs Established.
2. Allow TCP but break OPEN (ASN mismatch); TCP up, BGP not Established.
3. Lower MSS on a path; confirm large UPDATEs still complete after extended messages / packing.

## Risks

- Equating `ping` success with BGP transport health (ICMP ≠ TCP 179 policy).
- Symmetric ACL mistakes on multihop loopback peering.
- Aggressive CoPP that drops BGP TCP during bursts → mysterious Hold timeouts.

## Interview framing

“BGP runs over TCP/179 for reliable sessions, but TCP establishment only proves transport—OPEN, families, policy, and next-hop resolution still have to succeed before routing is useful.”
