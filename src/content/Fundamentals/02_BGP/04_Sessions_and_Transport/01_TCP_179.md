# BGP transport over TCP 179

BGP uses TCP port **179**. TCP provides reliable ordered bytes, retransmission, and fragmentation handling, allowing BGP to focus on routing state. The initiating side uses an ephemeral source port toward destination 179; either peer may initiate.

TCP health is not BGP health. A three-way handshake can complete while OPEN negotiation fails, and an Established BGP session can exchange zero accepted routes.

Network policy must permit both session initiation behavior and return traffic. Stateful firewalls, NAT, asymmetric paths, MTU issues, and control-plane policing can all affect the session.
