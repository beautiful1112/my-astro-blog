# Further reading

- Cisco Validated Designs / campus and WAN architecture guides (constraint-aware reading)
- IETF RFCs listed in [design RFCs](02_Design_RFCs_and_Architecture.md)
- Your own incident tickets: convert each into a [practical case](../19_Practical_Cases/README.md)
- Licensed commercial CCDE courses and books **you own**—use them as practice scenarios; do not treat any one book as the exam

This library is original study notes. It does not reproduce commercial book text or figures.

## How to use commercial books legally (study method)

Buy or borrow lawfully (publisher, bookstore, library, employer license). Do **not** copy chapters, figures, or question banks into this repo, chat logs you will publish, or shared drives. Fair study uses **your own words** and **your own diagrams**.

### Legal / ethical baseline

| Do | Do not |
|---|---|
| Purchase or license the title you study from | Download or share pirated PDFs / scans |
| Take handwritten or private notes in your own phrasing | Paste long verbatim excerpts into public notes |
| Sketch topologies from memory after closing the book | Re-draw publisher figures stroke-for-stroke for redistribution |
| Cite the book as a source (“see Author, Ch. N for scenarios”) | Treat one commercial book as the official exam |
| Use publisher practice scenarios as timing drills | Upload answer keys or copyrighted labs to the Internet |

### Study method (own the skill, not the pages)

1. **Read with a scenario lens** — For each chapter, write three lines: business need, constraints, one technology choice. Close the book first; then write.
2. **Rebuild, do not transcribe** — Redraw the topology from memory; label failure domains yourself. If you must peek, peek then redraw blank.
3. **One discard per chapter** — Force an option the book liked that *your* invented constraints would reject. That is CCDE muscle.
4. **Map to blueprint, not to page numbers** — Tag notes with blueprint domains (business, L2, WAN, DC, security), not “Book p. 214.”
5. **Time-box practice** — Use licensed practice exams/labs for pacing; review *why* an option fails R/C/A, not memorize letter keys.
6. **Cross-check with primaries** — When a book and the [official blueprint](01_Official_CCDE_Blueprint.md) or an RFC disagree on emphasis, prefer Cisco’s current topics list and protocol behavior.
7. **Feed this library** — Turn *your* incidents and lawful practice into [practical cases](../19_Practical_Cases/README.md) written originally here.

### What “good notes from a book” look like

```text
Source: <Title you own>, used <date> — private study
Scenario (my words): …
R/C/A (my extraction): …
Choice + discard: …
Failure / proof: …
Blueprint domain tag: …
```

No pasted paragraphs. No scanned pages. No shared answer dumps.

### Common failure modes when using books

| Failure | Fix |
|---|---|
| Highlighting every page | Close book; write R/C/A from memory |
| Collecting PDFs you did not buy | Delete; purchase or drop that source |
| Memorizing vendor “best” topologies | Force two constraints that break the topology |
| Ignoring blueprint updates | Re-download topics PDF each sitting window |
| Copying lab answers into shared notes | Keep private; rewrite as original cases here |
